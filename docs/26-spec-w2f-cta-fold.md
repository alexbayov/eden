## 2. Что именно сломано (измерено, не предположено)

Закреплённая нижняя полоса с главным действием привязана к `@media (max-width: 760px)`, поэтому её получают только телефонные ширины. На 768×1024, 1280×720 и 800×400 CTA остаётся в обычном потоке и уходит за сгиб.

Измеренные отступы от сгиба (отрицательное — за сгибом), `e2e/viewport-geometry.spec.ts`:

| Viewport | home | mission-select | reward | return | combat (ОГОНЬ) |
|---|---:|---:|---:|---:|---:|
| 768×1024 | +329 | **−1788** | −73 | **−188** | — |
| 1280×720 | +91 | — | **−311** | **−385** | — |
| 800×400 | **−295 и хуже на всех пяти экранах** | | | | |

Причины различны, и это важно для решения:

1. **768×1024 и 1280×720** — ширина выше breakpoint, полосы нет вообще. Ниже 1100 px шелл складывает канвас, панель и HUD в один столбец, а `.campaign-grid` складывает карточки, поэтому экраны стали выше сгиба.
2. **800×400** — двойственный случай: 800 px шире breakpoint (полосы нет), а 400 px высоты меньше шапки с панелью. Здесь проблема **высоты**, а не ширины.

## 3. Scope

**В scope.** Правило закреплённого CTA перестаёт зависеть **только от ширины**: добавляется условие по высоте, чтобы короткие и средние viewport получали полосу независимо от ширины. Использовать существующий токен `BREAKPOINTS.shortLandscape` (480) либо ввести новый именованный порог в `tokens.ts` — **литеральных px в CSS быть не должно** (правило `W8-01`).

**Вне scope.**
- Изменение игровой логики, контента, баланса — ничего из этого дефект не требует.
- Изменение раскладки на широких **и высоких** viewport (1400+), где CTA и так в сгибе: правка не имеет права ухудшить desktop.
- Визуальный регресс (`W1-08`) — заблокирован D-06.

**Явный риск, который я обязан проверить, а не предположить.** В doc 24 §7.2 зафиксирован эксперимент: возврат трёхколоночной `.campaign-grid` возвращает CTA в сгиб на desktop, но **ломает базовый CTA на 360×640**. То есть наивное расширение правила уже один раз давало регресс. Поэтому: любое изменение проверяется на **всех 25 комбинациях** viewport × экран, а не только на трёх проблемных.

**Второй риск — селекторы.** Закреплённая полоса ломалась дважды: один раз из-за `:last-child`, который поймал кнопку настроек (`W9-03`), второй — из-за позиционной привязки. Новые правила адресуются **по классу**, позиционные селекторы запрещены.

## 4. Отдельная находка: устаревший критерий в `W3-03`

Тикет `W3-03` критерий 5 утверждает: «в каталоге `base-upgrades.json` **один** апгрейд (`stash-2`) из шести необходимых… ответить на вопрос тикета нельзя». **Это неверно на текущем коде:** в каталоге **все шесть** (3 узла × 3 уровня, `MAX_NODE_LEVEL = 3`), их добавил пакет `W5-01`. Критерий стал измеримым, и он уже измерен: все шесть окупаются за **5 проходов** (металл 37 при нетто 8.26 за проход; ткань 12 при нетто 4.98 — узкое место металл).

**Дефект метрики, найденный при проверке.** `passesForAllUpgrades` считает **только** металл (`report.ts`: суммирует `upgrade.cost[REPAIR_MATERIAL]`). Сегодня ответ верен случайно — металл дороже по срокам; но если апгрейд подорожает по ткани, число не сдвинется и молча соврёт. Это надо починить, иначе метрика недоказуема.

## 5. Критерии приёмки

1. Главный CTA каждого из пяти экранов виден без прокрутки на **768×1024** и **1280×720** — измеренным `getBoundingClientRect`, а не визуально.
2. **800×400** разобран явно: либо CTA попадает в сгиб, либо, если это физически невозможно при 400 px высоты, зафиксировано **почему**, с числами, и заявлено как политика — но тогда дефект не считается закрытым и остаётся в §7.2 с обоснованием. Придумывать «прошло» для этого случая запрещено.
3. **Ни одна** из 25 комбинаций viewport × экран не деградировала: горизонтального скролла нет, все контролы ≥44×44 px, `withinFold` на 360×640 и 390×844 остался `true` на всех пяти экранах.
4. Baseline-таблица в `viewport-geometry.spec.ts` обновлена **осознанно**: каждый изменённый случай сопровождается новым измеренным числом, а полоса стабильности по шрифтам (`FOLD_STABILITY_MARGIN_PX`) сохранена — случаи, попадающие в неё, по-прежнему не утверждаются.
5. Ни одного литерального px-порога в CSS: порог — токен из `tokens.ts`, `tokens.css` перегенерирован `npm run tokens:build`.
6. `passesForAllUpgrades` учитывает **все** ресурсы стоимости апгрейдов, а не только металл; добавлен тест, который падает, если апгрейд подорожал по ткани, а число не изменилось.
7. Doc 24 §7.2 и §9.2 приведены к факту: дефект S2 закрыт (или сужен с обоснованием), статус гейта G2 пересчитан. `W3-03` критерий 5 переписан по факту, устаревшее утверждение снято явно.
8. `npm run verify` и `npm run test:e2e` зелёные; CI зелёный.

## 6. Тесты

- Расширение `e2e/viewport-geometry.spec.ts`: проверка сгиба на широких viewport становится **утверждением**, а не записью факта, для тех случаев, где дефект закрыт.
- Тест на экономическую метрику в `src/sim/cli.test.ts`: `passesForAllUpgrades` против каталога со подорожавшей тканью.
- Регрессия на селекторы: закреплённая полоса адресуется по классу — проверяется тем, что добавление контрола после CTA не меняет, какой элемент закреплён.
