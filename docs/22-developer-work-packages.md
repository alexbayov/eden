**Статус:** 🟢 v1.0, 22 августа 2026. Порядок выполнения — в [`21-delivery-plan-and-backlog.md`](21-delivery-plan-and-backlog.md).

## Как читать документ

Каждый тикет имеет фиксированную структуру:

- **Цель** — одно предложение.
- **Источники** — документы и файлы кода, задающие поведение.
- **В scope / вне scope** — граница работы.
- **Контракт данных/API** — что именно меняется в типах, JSON или публичных функциях.
- **Критерии приёмки** — проверяемые утверждения.
- **Тесты** — какие автоматические проверки обязательны.
- **QA** — ручные шаги, если они нужны.
- **Зависимости**, **Оценка** (S ≤ 0.5 дня, M ≈ 1–2 дня, L ≈ 3–5 дней), **Commit/PR**.

Общие требования ко всем тикетам:

1. Ветка `feat/<пакет>-<номер>-<краткое-имя>` или `fix/`, `chore/`, `docs/`, `test/` по типу работы.
2. Commit message: `<type>(<пакет>): <что и зачем>` в одну строку, тело — по необходимости.
3. PR обязан содержать разделы: **Что сделано**, **Что проверено**, **Что НЕ проверено**, **Затронутые документы**.
4. Ни один PR не мержится с красным `lint`/`typecheck`/`test`/`build`/`analyze:budget`.
5. **Запрещено** утверждать в коде, тестах, документах или PR, что браузерная/устройственная проверка состоялась, если её не было.
6. Изменение любой формулы или числа требует: владельца, версии, теста, обновления документа и кода в одном PR.

### Маркеры состояния

| Маркер | Значение |
|---|---|
| ✅ Ready | все зависимости и решения закрыты, можно брать |
| 🟡 Needs decision | ждёт решения владельца продукта (D-xx из doc 21 §9) |
| ⛔ Blocked (external) | требует ассетов, аудио или платформенной спецификации, которых нет |

**Цель.** Игра работает и вне платформы; интеграция подключается позже.

**Источники.** W10-01, `16-monetization.md`.

**В scope.** Интерфейс платформы (`init`, `saveCloud`, `loadCloud`, `leaderboard`, `ad`, `analytics`) с реализацией no-op по умолчанию; функциональность игры не зависит от наличия платформы; отсутствие сетевых запросов в no-op режиме.

**Вне scope.** Реальная интеграция (после W10-01). Реклама и покупки как механика.

**Контракт API.**

```ts
export interface Platform {
  readonly available: boolean
  init(): Promise<void>
  cloudSave?(payload: string): Promise<boolean>
  cloudLoad?(): Promise<string | null>
  submitScore?(board: string, value: number): Promise<boolean>
}
export const noopPlatform: Platform
```

**Критерии приёмки.**

1. Игра полностью проходится с `noopPlatform`.
2. Ни один игровой путь не блокируется отсутствием платформы.
3. В no-op режиме не выполняется ни одного сетевого запроса (проверяется E2E перехватом сети).
4. Никакой код игры не передаёт данные игрока третьим сторонам без явного действия пользователя.
5. Ошибка платформы деградирует безопасно, с сохранением локального прогресса.

**Тесты.** Полный happy path на no-op платформе; отсутствие сетевых вызовов. **QA.** E2E. **Зависимости.** W10-01 (частично; абстракцию можно писать раньше). **Оценка.** M.

**Commit/PR.** `feat(W10): add platform abstraction with safe no-op default`.
