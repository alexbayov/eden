# Релизный чек-лист

Владелец: `W10-04`. Гейты, на которые он ссылается, определены в [`docs/21-delivery-plan-and-backlog.md`](../docs/21-delivery-plan-and-backlog.md) §9; бюджеты — в [`docs/24-test-matrix-and-release-gates.md`](../docs/24-test-matrix-and-release-gates.md) §6.

## 1. Автоматическая часть — одна команда

```
cd code && npm ci && npm run verify && npm run test:e2e
```

`verify` = `lint` → `typecheck` → `validate:content` → `test` → `build` → `analyze:budget` → `analyze:release`. Ни один шаг не пропускается: `analyze:release` проверяет **собранный артефакт**, а не исходники, потому что часть правил иначе непроверяема — фикстура, которая законно лежит в репозитории, не должна попасть в `dist/`.

| Проверка | Команда | Что ловит |
|---|---|---|
| Статические бюджеты | `npm run analyze:budget` | initial JS > 150 kB gzip, ленивый бой > 1200 kB |
| Артефакт релиза | `npm run analyze:release` | нет версии в бандле; source map; тестовая фикстура в `dist/`; отсутствующий или лишний каталог; `console.log` в **нашем** коде; размер > 8 МБ |
| Контент | `npm run validate:content -- --strict-playability` | недостижимые клетки цели, битые ссылки, непроходимые карты |
| Runtime-производительность | `npx playwright test e2e/performance.spec.ts` | выход за бюджеты doc 24 §6.2; пишет отчёт в `design-data/perf/` |

Коды выхода `analyze:release`: `0` чисто, `1` артефакт неверен, `2` проверка не смогла выполниться (нет сборки). Третий код существует отдельно, потому что «не смог проверить» и «проверил, всё плохо» — разные события, и путать их значит получить зелёный гейт из сломанного скрипта.

## 2. Воспроизводимость

Критерий 1 тикета: сборка из чистого клона одной командой даёт артефакт **одинакового состава**. Проверяется так:

```
git clone <repo> /tmp/eden-release && cd /tmp/eden-release/code && npm ci && npm run build
diff <(cd /tmp/eden-release/code/dist && find . -type f | sort) <(cd code/dist && find . -type f | sort)
```

Совпадать обязан **состав** файлов. Имена чанков содержат хеш содержимого, поэтому побайтовое равенство имён — следствие равенства кода, а не отдельное требование.

## 3. Версия

Версия берётся из `code/package.json` и попадает в бандл через `__APP_VERSION__` (`vite.config.ts`). Она обязана быть видна игроку — выводится в шапке рядом с `EDEN //` — и присутствовать в артефакте; второе проверяет `analyze:release`. Релиз, который нельзя опознать, невозможно сопоставить с баг-репортом.
