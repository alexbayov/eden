## 2. Граница scope плана

Этот план ведёт проект от текущего M3-D alpha к **release candidate полного MVP** по границам [`20-mvp-scope-and-roadmap.md`](20-mvp-scope-and-roadmap.md): 4 зоны, 6 типов врагов, 7 оружий, 8 ресурсов, 3 уровня базы, 10–15 часов основного контента, desktop + mobile, без P2W.

**Внутри плана:** инженерная реализация, QA-инфраструктура, баланс, интеграция контента и ассетов, подготовка релиза.

**Вне плана:** производство арта и звука (внешняя работа, см. §10), финальные тексты нарратива, платформенные юридические/консент-требования, серверная часть (cloud save, authoritative leaderboards, anti-tamper).

**Допущение по ресурсам:** один разработчик full-time, владелец продукта — part-time для решений. План **последовательный**: параллельные треки не запланированы, потому что почти каждый пакет зависит от QA-инфраструктуры и решений по балансу.

1. Ни один тикет не начинается до `W0-01`.
2. Ни один UX-тикет с утверждением о геометрии или тач-вводе не закрывается до `W1-05`.
3. Ни один тюнинг чисел не закрывается до `W3-04`.
4. Ни одна новая сущность в сохранении не добавляется до `W4-05`.
5. Пакеты, зависящие от WS-EXT, не стартуют до поступления ассетов и спецификаций (см. §10).

## 8. Definition of Ready / Definition of Done

### Definition of Ready (тикет можно брать)

1. Есть цель одним предложением и явный источник (документ или файл кода).
2. Перечислено, что **вне** scope тикета.
3. Контракт данных/API описан или явно указано, что не меняется.
4. Критерии приёмки проверяемы автоматически или ручным скриптом.
5. Все зависимости закрыты, все нужные решения владельца приняты.
6. Указана оценка S/M/L.
7. Если тикет требует ассетов или платформенной спецификации — они уже поступили.

### Definition of Done (тикет закрыт)

1. `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, `npm run analyze:budget` зелёные.
2. Новое поведение покрыто тестом, который падает без изменения.
3. Если тикет затрагивает UI/ввод — есть E2E или DOM-проверка, а не только статическая.
4. Если тикет затрагивает числа — есть прогон симулятора или граничный тест.
5. Обновлены затронутые документы 09–24 и статус в `00-index.md`.
6. Изменение закоммичено в ветке и отправлено в PR; PR описывает что проверено и **что не проверено**.
7. В документах нет утверждений о браузерной/устройственной проверке, которой не было.
8. Временные файлы и отладочный код удалены.

## 10. Что нельзя реализовать сейчас

Следующие пакеты **не могут быть начаты** и не входят в оценку сроков до появления внешних входов:

- **W8-03…W8-05 (арт-интеграция).** Нет ни одного production-ассета: в `code/src/assets/` только `hero.png`, `preact.svg`, `vite.svg`, в `public/` — `favicon.svg` и `icons.svg`. Каталог `art/` отсутствует и создаётся в `W8-02`.
- **W9-01, W9-02 (аудио).** Нет ни одного звукового файла и нет лицензионного реестра.
- **W10-01…W10-03 (платформа).** Нет локальной спецификации платформенных API; ни одна интеграция не подтверждена.

> **Явное ограничение.** [`13-narrative-and-setting.md`](13-narrative-and-setting.md), [`15-audio-design.md`](15-audio-design.md) и [`19-art-and-design-brief.md`](19-art-and-design-brief.md) — это **направления и требования, а не реализуемые спецификации**. Прежде чем стартуют W7-03/W7-04 (нарративный контент), W9-01/W9-02 (аудио) и W8-03…W8-05 (арт), для каждого из этих трёх документов нужен отдельный implementation spec с конкретным перечнем ассетов/текстов, их id, форматами, размерами, лицензиями, автором и fallback-поведением. До этого соответствующие тикеты остаются в состоянии **Blocked (external input)** и не считаются частью восьминедельного объёма.
