## B. Сравнение движков

### B.1 Godot 4 (Web export)

**За:**
- Полноценный визуальный редактор (сцены, коллизии, UI)
- GDScript максимально дружелюбен к ИИ-агентам
- Native tilemap с изометрией из коробки (R9)
- Отличная UI-система (Control nodes) для сложных экранов (R11)
- 2D-производительность топовая
- Огромное сообщество, много туториалов
- Есть Yandex Games SDK plugin

**Против:**
- **Размер веб-билда — главная боль.** Дефолтный wasm ~30-33 МБ. С brotli-сжатием и custom-сборкой можно ужать до 2.4-13 МБ, но это **требует пересборки движка через SCons**.
- Mobile performance на webview — приемлемая, но не блестящая.
- Отладка веб-билда сложнее чем нативного.

**Оценка:** 7.5 / 10 — мощный, но веб-размер это боль.

### B.2 Phaser 3 (+ TypeScript)

**За:**
- **Целевая платформа = веб.** Никаких wasm. Билд = HTML+JS+ассеты, обычно 3-10 МБ.
- Идеально совместим с Яндекс.Играми.
- TypeScript = ИИ-агенты работают на нём отлично (R7).
- **OpenAI построила турбовую RPG на Phaser 3 через GPT-5.4** (март 2026) — прямое подтверждение.
- Grid Engine plugin — готовая изометрическая grid-система с pathfinding.
- Tiled integration (R9).
- Тач-управление нативно (R10).

**Против:**
- Нет визуального редактора. Всё пишется в коде + Tiled для карт.
- UI — боль. Нет встроенной UI-системы для сложных экранов. Решается гибридом: Phaser Canvas для игры + Preact/React DOM поверх для UI.
- Прошлый негативный опыт разработчика с Phaser скорее всего из-за отсутствия готовой боёвки — но для **пошагового** боя это плюс: State Machine + Grid + Turn Manager под контролем.

**Оценка:** 8.5 / 10 — целевой для веба, ИИ-дружественный, лёгкий билд.

### B.3 Defold

**За:** Специально оптимизирован для веба и мобилок. Билды ~2-5 МБ.
**Против:** Lua-скриптинг (ИИ-агенты работают хуже), меньше сообщества, меньше документации на русском.
**Оценка:** 6 / 10.

### B.4 Construct 3

**За:** Визуальное программирование, быстрый прототип, поддержка Яндекс.Игр.
**Против:** Не подходит для сложной пошаговой боевой логики. Event-система нечитаема для больших state machines. ИИ-агенты слабо работают с event sheets. Подписка $99/год.
**Оценка:** 4.5 / 10.

### B.5 PixiJS + собственная архитектура

**За:** Максимальный контроль, лёгкий рантайм.
**Против:** Всё писать с нуля — 3-6 месяцев до первой строчки геймплея.
**Оценка:** 4 / 10.

### B.6 Unity WebGL

**За:** Мощный движок, много туториалов, ИИ-агенты работают.
**Против:** Билды 15-30 МБ. Медленный старт на мобильных (5-15 секунд). Оверкилл для 2D.
**Оценка:** 5.5 / 10.

## D. Рекомендация критика: **Phaser 3 + TypeScript** ✅ УТВЕРЖДЕНО

### Почему:

1. **Веб — родная платформа.** Zero-effort экспорт под Yandex Games. Размер билда 3-10 МБ vs 30+ у Godot.
2. **ИИ-агенты работают на TypeScript блестяще.** Claude/Copilot/Cursor выдают качественный TS-код лучше, чем GDScript.
3. **Пошаговый бой — это чистая логика.** State Machine + Grid + Turn Manager — три чистых класса на TS. Никаких лишних абстракций.
4. **OpenAI сама выбрала Phaser** для демонстрации ААА-подобной турбовой RPG в марте 2026 — независимое подтверждение связки "ИИ-агент + Phaser".
5. **Grid Engine plugin** решает изометрию, pathfinding и коллизии из коробки.
6. **UI-гибрид:** игровые сцены на Phaser Canvas, сложные UI-экраны (инвентарь, крафт, база) на Preact DOM поверх. Стандартная практика топовых Phaser-игр.

### Стартовый стек (утверждено):

```
Phaser 3.90+ (latest)
TypeScript 5.6+
Vite (bundler, быстрый dev)
Grid Engine (isometric grid + pathfinding)
Tiled Map Editor (для карт)
Zustand или Nanostores (state management)
Preact (UI-экраны поверх canvas)      ← ✅ выбрано владельцем
Framer Motion (UI-анимации, красота)   ← ✅ выбрано владельцем
Lucide (иконки)
Howler.js (audio)
LocalForage (сохранение)
Yandex Games SDK (реклама, лидерборды, IAP)
Zod (валидация JSON-данных)
```

Всё Open Source, всё дружит с ИИ-агентами, всё грузится быстро.
