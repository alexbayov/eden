# 03 — Critic Loop

**Статус:** 🟢 v1.0. Назначение: обязательный цикл критики до content lock.

## Цикл

| Шаг | Вход | Результат | Владелец |
|---|---|---|---|
| 1. Гипотеза | задача/формула/экран | критерий успеха и риск | design |
| 2. Реализация | ветка или прототип | тестируемая сборка | engineering |
| 3. Проверка | сценарий QA + 3–5 плейтестов | факты, не мнения | QA/design |
| 4. Критика | данные, фидбек, видео | P0/P1/P2 список | critic |
| 5. Решение | варианты с ценой | accept/reject/defer | product |
| 6. Нормализация | принят��е решение | docs, tests, changelog | owner документа |

## Правила

- Критик не меняет scope сам: он формулирует наблюдение, доказательство, риск и вариант.
- P0 блокирует следующий этап; P1 закрывается до content lock; P2 попадает в backlog.
- Одна формула имеет один источник. Изменение требует граничных тестов: минимум, норма, максимум.
- Прототип оценивается отдельно от спецификации: «работает в `code/`» не означает «готово для MVP».

## Карта обязательных ревью MVP

| Веха | Вопрос | Acceptance criteria |
|---|---|---|
| Combat slice | выбор части тела меняет решение? | 80% тестеров объясняют шанс и эффект до выстрела. |
| Mobile slice | возможно ли пройти бой одним большим пальцем? | все критические действия доступны без hover и без точности пикселя. |
| Economy slice | есть ли тупик после смерти? | тестовый профиль восстанавливается за ≤2 нормальные вылазки. |
| First hour | понятна ли цель «Эдем»? | игрок называет текущую и следующую цель без подсказки. |
| Release candidate | нет ли денежной силы/темпа? | QA не находит платного изменения урона, шанса, энергии, таймера или лута. |

## Шаблон критической записи

| Поле | Содержание |
|---|---|
| ID/версия | например COM-07 / v0.1 |
| Факт | воспроизводимое наблюдение |
| Доказательство | тест, запись, метрика |
| Влияние | игрок, баланс, сроки |
| Приоритет | P0/P1/P2 |
| Варианты | 1–3 с ценой разработки |
| Решение | владелец и дата |

## Открытые решения

## Post-MVP

Еженедельный review retention/экономики, regression-набор по инцидентам и публичный backlog улучшений.
